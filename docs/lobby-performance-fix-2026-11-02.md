# 로비 성능 수정 — 2026-11-02

## 적용

- 공연장 생성은 동일한 generator recipe를 사용하되 브라우저에서는 약 5ms 작업 예산마다 다음 프레임으로 넘긴다. 벽/오르간/조명, 좌석, 단원, architecture/character batching에 중간 반환 지점을 추가했다. 동기 geometry 소비자용 API도 유지한다.
- GPU 준비도 소수 batch씩 compile/upload한다. 실제 화면에 그리는 대상만 준비하고, 보이지 않는 좌석/바닥 클릭 판정 mesh와 빈 instance batch는 제외한다. 실제 batch의 버퍼를 재사용하므로 복제 instance buffer/VAO를 만들지 않는다. 준비 중 임시 분리된 mesh는 각 작업의 finally에서 복구한다.
- 공연장 준비 중 반복 입장 요청을 막고, 준비가 끝난 뒤 zone을 바꾼다. 재접속으로 공연장 snapshot이 먼저 와도 마지막 snapshot을 보관해 완료 후 적용한다.
- 좌석 지도는 한 번 준비해 재사용한다. 숨겨진 상태에서 버튼을 32개씩 준비하고, 안정된 callbacks와 memo로 불필요한 전체 재생성을 줄인다. 440개 좌석과 키보드 접근성을 유지한다.
- 지도/설정 뒤의 장면은 8Hz, 입장 전 정지 전경은 30Hz, 숨겨진 탭은 1Hz로 갱신한다. 이동 중 품질/해상도 설정은 유지한다. 오디오는 기존 독립 100ms timer로 동작한다.
- dialog에 키보드 초점이 있을 때 이동 키가 캐릭터에게 전달되지 않게 했다.
- 모든 작은 architecture mesh를 2.5m 이내에서 숨기던 일반 규칙을 제거했다. 난간·계단·기둥이 보존된다. 명시적으로 지정한 벽 마감/장식 가림은 유지한다. 로비 목재 마감도 명시적 가림 대상으로 지정해 카메라를 가리는 마감 면이 물러나도록 했다.
- 벽 충돌로 카메라가 내 캐릭터에 너무 붙는 경우 자기 캐릭터만 숨겨 시야를 확보한다. 캐릭터 모델/의상/동작은 변경하지 않았다.
- 반응 아이콘이 없는 동안 비어 있는 emote buffer를 매 프레임 GPU에 다시 올리지 않는다.
- 실제 사용하는 Noto Serif KR 400만 요청하고 사용하지 않는 500/600 폰트 CSS 요청을 제거했다.

## 검증

- `npm run check`, `npm run build`, `git diff --check` 통과. 자동 테스트 명령은 실행하지 않았다.
- Ego Chromium에서 배포용 production build를 localhost:4173으로 열어 검증했다. 기존 공개 사이트 측정과 네트워크 조건은 다르므로 초기 로딩 시간의 직접 비교는 하지 않는다.
- 공개 사이트에서 동기 공연장 생성만 136~232ms가 관측됐다. 수정 후 생성 slice는 보통 5~20ms 수준이었으며 빠른 입장 최종 측정의 최대는 49.9ms였다. 5ms는 협력적 예산이며 개별 동기 작업의 엄격한 상한을 보장하지 않는다.
- GPU 업로드 분할의 최종 빠른 입장 측정: 93개 묶음, 최대 20.1ms. 버전 중간의 50~72ms 결과를 확인한 후 판정 물체 제외와 묶음 축소를 적용했다.
- 일반 로비 정면 및 2층 이동에서 약 75FPS 관측. modal 중 8FPS 관측. 해상도는 1313×1370 / pixelRatio 약 1.479로 유지했다.
- 2층 난간 연결, 벽 근처 캐릭터 가림, 실제 1층 22열 8번 착석과 앉은 시점 드래그를 화면으로 확인했다.
- 좌석 지도 재열기 시 Long Task가 기록되지 않았다. modal을 연 약 2.25초 동안 음악도 약 2.25초 진행했고 paused=false/readyState=4를 유지했다.
- 준비 완료 전 즉시 입장, 공연장 입장 후 로비 복귀도 통과했다. 마지막 빠른 입장 측정에서 error/unhandledrejection 수집 결과는 비어 있었다.
- 공연장 440개 좌석과 103명 musician/conductor actor가 생성되는 것을 확인했다.

## 남은 제한

- 최초 로비 생성·JS 실행/첫 렌더에는 여전히 50ms 이상 긴 작업이 관측됐다. 초기 검은 화면/모든 순간 멈춤이 완전히 사라졌다고 보장하지 않는다. 전체 화질 삭감으로 감추지 않았다.
- 아이폰 13 Pro 실기기, iOS 오디오 잠금 해제, 발열/메모리, 많은 동시 관객은 이번 로컬 검증에 포함되지 않았다.
- iOS 오디오 권한 처리에는 회귀 위험이 있어 `unlock()`의 실제 곡 사전 다운로드 방식은 바꾸지 않았다. 로비에서 데이터가 미리 내려오는 문제는 별도의 실기기 확인이 필요하다.
- 천장/안내문 텍스처 재압축·atlas는 병목으로 확정되지 않아 이번 수정에서 적용하지 않았다. 천장 그림, 악기, 좌석 디테일은 유지했다.
- GitHub push/공개 사이트 배포는 수행하지 않았다. 공개 URL의 수정 효과는 배포 후 같은 경로로 다시 확인해야 한다.

## 시작 미리보기의 화각 점프 추가 수정

- 기존 1600×1000 미리보기의 `object-fit:cover`가 화면 비율에 따라 확대/잘림을 바꿨다. 실제 카메라는 세로 화각 61도(가로/일반), 70도(세로)로 그리므로, 초기 미리보기에서 3D로 넘어갈 때 구도가 달라졌다.
- 실제 로비 시작 카메라로 3200×1000, 세로 화각 70도 미리보기를 다시 렌더했다. CSS는 cover 대신 카메라 투영에 맞는 높이/중앙 잘림을 사용한다. 61도 화면의 배율은 tan(35°)/tan(30.5°)=1.1887165135이고, 세로 70도 화면은 1이다. 모바일 주소 표시줄 변화에는 dvh를 사용한다.
- Ego에서 1600×900, 390×844, 888×927 화면으로 미리보기와 준비 완료된 3D 화면을 각각 캡처해 정면 문/창문/난간의 크기와 위치가 일치하는 것을 확인했다. 390×844는 화면 크기 재현이며 iPhone 실기기 검증은 아니다.
- 타입 검사/배포용 빌드 통과. 이 수정도 로컬 상태이며 push/배포하지 않았다.

## 문/그림 중첩·좌우 벽 떨림·입장 깜빡임 수정

- 뒤쪽 ±8.4 위치의 문과 겹치던 ±7.7 그림 패널 두 개를 제거했다. 문을 유지하고 공연장과 같은 패널/손잡이가 있는 목재 문으로 정리했다. 바깥쪽 ±11.9 그림은 유지했다.
- 좌우 연속 목재 배경은 뒤로 물러난 단일 배경 면만 만든다. 배경의 반복 인셋 면과 개별 그림 패널의 목재 앞면이 같은 깊이에 놓여 생긴 z-fighting을 없앴다. 윗부분 전후 벽도 같은 배경 규칙을 적용했다. 개별 패널/몰딩과 나무 텍스처는 유지했다.
- 입장 전에 쓰던 임시 위치 (0,0,10)를 서버 시작점 SPAWN.lobby=(0,0,24)로 통일했다. start()에서 서버 초기 snapshot과 같은 yaw=π/카메라를 즉시 설정한다. 연결 전 잠깐 로비 밖을 바라본 뒤 서버 응답으로 시점이 튀는 현상을 막았다.
- 수정 전에는 entered=true/self=false 프레임이 z=10/yaw=0이었고, 연결 후 z=24/yaw=π로 바뀌었다. 수정 후 연결 전후 위치 z=24와 카메라 좌표(약 0,1.6722,19.2405)/yaw=π가 동일하게 기록됐다.
- 양쪽 문과 양쪽 벽을 Ego 화면에서 확인하고, 최종 production build의 입장 프레임도 기록했다. 타입 검사·빌드·diff 형식 검사 통과. 수정된 벽면으로 시작 미리보기 이미지도 다시 렌더했다.
- 이전 최적화/화각 수정은 유지했으며 GitHub push/공개 배포는 하지 않았다.
