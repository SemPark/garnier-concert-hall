## 기록한 검증

- 시간 경계·목록 반복·잘못된 음원 길이·좌석 도달 경로 등 단위 테스트 9개 통과.
- 실제 로컬 Durable Object 대상 통합 검사: 입장·구역 전환·좌석 중복 방지·멀리서 착석 거절·이동 후 착석·토큰 재접속·좌석 반환·오래된 취소 요청 보호·시계 응답·20개 연결 통과.
- 빌드된 앱의 `/api/audio/` 경로에서 HTTP Range 요청에 206과 요청한 1,024바이트를 반환하는 것을 확인. 정적 자산 응답에 파일 길이가 없을 때 빌드 시 생성하는 음원 파일 크기 목록을 사용하며, 전체 음원을 메모리에 읽지 않고 스트림에서 필요한 구간을 전달한다.
- 실제 브라우저 UI로 입장 → 공연장 → 좌석 선택 → 경로 이동 → 착석을 확인.
- 착석 후 48초 테스트 음원의 반복 시작 구간에서 실제 재생 위치와 계산 위치 차이 약 0.063초를 한 번 관측. 이는 여러 실제 기기의 장시간 동기화 성능을 보장하는 측정이 아니다.
- 같은 브라우저 환경의 한 장면에서 그리기 호출 수를 약 1,097회에서 151회로 줄임. 반복 건축 모듈과 연주자 부분을 인스턴스로 렌더링한다. 연주자 동작은 여전히 각자 계산한다.
- 브라우저에서 약 30fps를 관측. 브라우저 구동 환경의 프레임 제한 여부를 분리하지 않았으며 기기 성능 기준으로 확정하지 않음.
- 390×844 모바일 화면 에뮬레이션에서 가로 넘침과 화면 밖 버튼이 없는 것을 확인. 실제 터치·기기 검증은 남음.

검증 화면은 `concert-hall/artifacts/`에 저장했다. 실행·음원 교체는 `concert-hall/README.md`를 참고한다.

## 2026-10-31 단 중앙 정렬과 실제 지지면 검증

후속 요청에 따라 원본의 파트별 악기 수량은 유지하고, 픽셀 좌표 대신 곡선 단의 줄 중앙에 단원을 배치했다. 앞줄 6명으로 중앙 공백을 줄이고, 두 바이올린 파트는 왼쪽, 비올라·첼로는 오른쪽을 유지한다. 현악의 공유 보면대는 같은 줄끼리만 묶는다. 마지막 단의 왼쪽 날개를 넓혀 하프·첼레스타·피아노의 전체 범위를 지지한다.

의자 네 발만 확인하던 검사에 실제 단 메시를 향한 수직 레이 검사를 추가했다. 다리·의자·보면대·바닥 악기의 모든 정점 수평 범위가 동일 단 위에 있어야 한다. 원본 수량은 렌더링용으로 생성된 악기 모델 수도 대조한다. 하프 등 양 끝 단원이 감상 시점에서 잘리지 않도록 카메라를 조정했고, 전체 오케스트라가 프레임 안에 드는 검사를 추가했다.
