# 산사에서 확인한 구현과 적용 범위

확인일: 2026-10-30. 근거: https://sansatemple.com/assets/game-D9JTEbm0.js

공개 배포된 압축 자바스크립트와 브라우저의 자산 요청을 읽었다. 원본 저장소나 서버 코드를 확보한 것은 아니다.

| 확인한 사실 | 공연장에 적용할 방향 |
|---|---|
| 렌더러가 `three.js r180`으로 식별됨 | Three.js 장면·카메라·조명 구조 사용. 새 프로젝트 버전은 구현 시 검증 |
| 바닥 클릭을 레이캐스트로 판정하고 경로를 따라 이동 | 로비·객석 통로의 이동 가능 영역과 클릭 이동 구현 |
| 드래그 회전, 휠 거리 조절, 핀치, WASD/방향키 지원 | 조작 의미와 반응을 기준으로 카메라·입력 구현 |
| 기본 카메라 거리 3.85, 거리 범위 2.2~14, 회전·상하 각 제한 | 동일 조작감의 시작값으로 참고하고 새 캐릭터 크기·공간 단위에 맞게 조정 |
| `monk.glb`와 `monk-remote-lod.glb`를 나누어 로딩 | 공통 캐릭터와 가벼운 원격 관객 표현 |
| 모델 관절을 코드로 회전·보간하고 팔 위치를 계산 | 걷기·앉기 및 단순 연주 동작을 공통 관절 구조에서 구현 |
| 근거리 일부만 상세 모델로 표시하고 먼 캐릭터의 갱신을 줄임 | 오케스트라·관객의 거리·가시성 기반 최적화 |
| Cloudflare workers.dev의 WebSocket 주소로 접속 | 방별 WebSocket 서버를 별도로 설계 |
| 상태 스냅샷·버전별 변경·재동기화·재연결·좌석 요청 처리 | 접속 복구와 좌석 중복 방지를 처음부터 구조에 포함 |
| 외부 접속 경로의 위치 전송 간격 500ms | 전송 빈도와 화면 보간을 분리하고 새 공간에서 조정 |
| 클라이언트에 방 100개·방당 100명 상수 | 참고값만 보관. 실제 수용 성능으로 해석하지 않음 |
| 서버 시간 차이를 구하고 정해진 시작 시각에서 음원 위치 계산 | 상시 공연 목록의 공통 기준 시각과 중간 입장 구현 |
| HTML audio를 Web Audio에 연결, `currentTime`으로 재생 위치 설정 | 음악 파일을 각 기기에서 재생하고 위치 보정 |
| 건축 장면 구성, 재질 이미지, 벽화, 불상 GLB를 조합 | 가르니에를 반복 건축 모듈·장식 텍스처·별도 소품으로 구성 |
| 화면 픽셀 비율 제한, 그림자 선택 갱신, 초기 장면 뒤 외부 자산 로딩 | 초기 로딩·모바일 비용을 제한하는 성능 예산 도입 |

코드 전체를 개조하는 방식보다는 확인한 설계와 동작을 토대로 공연장에 필요한 모듈을 새로 작성하는 계획이다. 공연장·악기·연주 동작·곡 목록 운영은 새로 구현해야 한다.
