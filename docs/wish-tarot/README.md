# PLEEE 소원 타로 — 3장 시안 제작·통합 설계

작성일: 2026-11-13. 검토 기준: `optimization`, HEAD `55c82f6`와 현재 미커밋 작업.
상태: 사용자 요청에 따라 메이저 아르카나 22장을 완성해 로컬 체험에 연결했다. 이전 시안 3장과 새로 생성한 19장을 공통 프레임으로 합성한다. 아래 세부 설계에는 초기 시안 기록과 향후 온라인 동기화 계획이 포함돼 있다.

- 차·카드 게임·타로 착석 안내에 44px 터치 영역의 X를 추가했다. 안내를 닫은 뒤 착석을 유지하며, 자리에서 일어났다 다시 앉으면 안내가 열린다.
- 세 뒷면에 22장 중 서로 다른 카드를 균등 배정한다. 고른 앞면 한 장만 요청하며 실패하면 같은 카드의 그림을 재시도한다. 결과에서 꽃다발을 받거나 닫으면 두 캐릭터가 뽑은 카드가 꽂힌 꽃다발을 건넨다. 추첨과 선물 연출은 현재 방문자 화면에서 처리한다.
- 앱용 앞면은 모두 768×1152 WebP다. 로컬 [22장 비교 화면](http://127.0.0.1:5173/docs/wish-tarot/preview.html)에서 전체 그림과 해석을 볼 수 있다. 내장 이미지 생성에 사용한 지시문은 `deck-prompts.json`에 기록했다.

### 초기 시안 및 통합 기록

- `TAROT_HOST_SEAT`로 랜턴 캐릭터의 기존 8번 테이블 3번 자리를 공유 정의했다. 그 앞에 자주색 작은 테이블보, 금색 가장자리, 타로 뒷면 3장을 배치했다.
- 뒷면은 코드 SVG 한 장을 공유하며, 장면의 세 카드는 InstancedMesh 한 개다. 소품 전체는 3 draw calls와 작은 텍스처 1개로 구성하며 새 조명은 없다.
- 실제 착석·본인 seated claim을 확인한 뒤 하트 여왕과 같은 위치/크기의 ‘소원 타로’ 아이콘을 표시한다. 타로 아이콘은 별 문양으로 구분한다.
- 아이콘을 누르면 세 시안의 뒷면 버튼이 열린다. 하나를 선택하면 생성된 그림·공통 코드 프레임·정확한 번호/이름·확정 해석이 확대 표시된다. ‘다른 시안 보기’로 세 장 모두 확인할 수 있다. 시안 화면임을 명시하며 전체 22장 균등 추첨으로 오인시키지 않는다. 닫기/Escape는 착석을 유지하고 아이콘으로 포커스를 되돌린다. 자리 상실·연결 해제·사진 모드는 창을 닫는다.
- `npm run check`, `npm run build`, 관련 테스트 32개, NPC 좌석 로컬 Worker 통합 검증, `git diff --check` 통과. 실제 로컬 좌석맵으로 8번 테이블 착석 → 아이콘 → 앞면 공개 → Escape 경로를 확인했다. 닫은 뒤 착석 유지·아이콘 포커스 복귀·앞면 DOM 제거를 확인했다. 여왕 테이블은 여왕 아이콘만 표시한다.
- 390×844 브라우저 화면에서 새 장식 프레임과 확정 해석 표시, 가로 넘침 없음, 선택한 앞면 이미지 하나만 DOM에 유지됨을 확인했다. 세 시안 모두 로드·표시를 확인했다. 실제 iPhone FPS·메모리 실측은 아직 없다.
- 후속 사용자 선택으로 원본 임시 사용 대신 새 화풍 3장만 제작했다. 내장 생성 총 5회(신규 3+수정 2), 외부 유료 API/크레딧 서비스 호출 없음. `generation-notes.md`에 실제 생성 지시문·검수·미완료 사항을 기록했다. 탑의 금빛 불씨는 현재 26개로 설계 목표 22개에 대한 후속 보정 대상이다.
- 앱용 WebP는 768×1152, 각 약 249~298 KiB이며 선택한 그림 하나만 로드한다. PNG 원화는 `artwork/`, 비교 화면은 개발 서버의 `docs/wish-tarot/preview.html`에 보존한다.
- 사용자 첨부 프레임을 참고해 단순 직선 테두리를 꽃·백합·회녹색 잎·청회색 덩굴 패널·상단 번호 장식·하단 접힌 리본이 있는 아르누보풍으로 교체했다. `TarotFrameOrnament.tsx`의 공통 SVG를 사용하며 이번 프레임 수정에는 이미지 생성 호출이 없다. 원화 전체 비율을 유지하고 카드 주요 상징은 가리지 않는다.
- NPC 좌석 점유 문제는 사용자 요청에 따라 좌석 예약 금지로 해결했다. NPC 의자 5개는 유지하고 `SEATS`/`CAPACITY`는 방문객용 123석을 나타낸다. 서버·LocalConcert에서 직접 예약/착석을 거절하며 이전 NPC 좌석 세션은 해제한다. 하트 여왕 앞에도 붉은 테이블보를 추가하고 큰 시계는 런타임 장면에서 제거했다.

## 1. 이번 검토에서 결정할 것

**아이보리 바탕에 오래된 금박과 버건디를 사용한 고전 회화·동판화풍**을 제안한다. 태양·별·탑은 서로 다른 화풍 후보가 아니라, 같은 화풍이 밝은 장면·고요한 장면·극적인 장면에 모두 맞는지 확인하는 세 시안이다.

1. 이 문서의 스타일·구도 계획을 사용자에게 확인받는다.
2. 생성 경로의 별도 과금 여부를 확인한다. 유료이면 모델·해상도·수량·재시도 포함 상한을 견적 내고 명시적 승인을 받는다.
3. 태양 1장을 먼저 생성·검수하고, 그 결과를 스타일 기준으로 별과 탑을 각각 생성한다. 최초 시안은 총 3장이다.
4. 코드로 같은 테두리·번호·제목을 합성한 세 시안을 보여준다. 사용자 스타일 확정 전 나머지 19장은 생성하지 않는다.
5. 확정 후 같은 기준으로 19장을 제작하고, 로컬 통합 및 iPhone 검증을 진행한다. 운영 배포는 별도 요청 범위다.

최초 계획은 서로 다른 그림 3장, 각 1회였다. 이후 사용자의 3장 시안 제작 선택에 따라 실제 내장 생성 5회(신규 3+별·탑 수정 각 1회)를 사용했다. 외부 유료 생성 API 호출은 0회다. 나머지 19장은 생성하지 않았다.

기본 후보는 내장 ImageGen이다. API 키가 필요 없다는 점만 확인했으며, 계정별 별도 과금 여부나 단가는 확인되지 않았다. 무료라고 단정하지 않으며 확인되지 않은 금액을 견적으로 제시하지 않는다. 유료 API·Higgsfield 크레딧 경로로 자동 전환하지 않는다. 유료 경로라면 `3 × 해당 해상도·품질의 이미지 단가 + 참조 이미지 입력 비용`을 확인하고, 통화/크레딧·총상한·포함 수량을 제시한 뒤 승인받는다. 지금은 디자인 확인 단계이며 비용 승인이 아니다.

### 코드 합성 템플릿

- 완성 카드 비율은 3:5. 공통 SVG 좌표계는 600×1000이다.
- 그림 영역은 `(x=56, y=122, width=488, height=732)`로 고정한다. 2:3 그림을 자르지 않고 담는다. 꽃 장식은 그림 가장자리에 조금 겹치되 주요 장면과 번호·제목은 가리지 않는다.
- 상단 번호 장식, 하단 영문 제목 리본과 한글 이름, 아이보리 여백, 오래된 금색 선, 청회색 바탕의 꽃·잎·덩굴 장식은 한 React/SVG 템플릿에서 생성한다. SVG 정의에는 인스턴스별 ID를 붙여 세 장을 함께 표시해도 충돌하지 않는다.
- 번호는 `0, I…XXI`를 데이터에서 그대로 표시한다. RWS의 `VIII 힘`, `XI 정의`를 유지한다. 영어 이름은 사용자 표의 `Judgement` 등을 그대로 사용한다.
- 한글은 본고딕/명조 계열 중 실제 번들 및 라이선스를 확인한 서체를 고정한다. 긴 이름인 ‘운명의 수레바퀴’까지 동일 박스에서 검증한다. 웹폰트를 쓰면 합성 전에 로딩 완료를 기다린다.
- 내보내기가 필요할 때만 동일 SVG 템플릿을 래스터화한다. 생성 모델에 제목이나 로마 숫자를 쓰게 하지 않는다.
- 뒷면은 한 종류: 버건디 바탕, 금색 이중선, 장미·백합 덩굴의 대칭 선화. 코드 벡터로 만들 수 있으며 22장의 앞면 그림을 대체하는 용도가 아니다.
- 결과 카드 아래에는 별도로 번호·카드 이름·확정 해석을 읽을 수 있게 표시한다. 장식용 템플릿과 스크린리더의 중복 낭독은 피한다.

## 3. 세 시안의 구성

원본 링크는 사용자 지정 1909년 Roses & Lilies 판본이다. 세 원본의 그림을 실제로 열어 확인했다. 파일 페이지는 Pamela Colman Smith의 그림, Saskia Jansen 소장본 스캔으로 안내하며 Public Domain Mark를 표시한다. 원본은 상징·구도 참고이며 앱에 넣을 그림은 새로 생성한다.

| 카드 | 반드시 보존할 장면·상징 | 이번 시안의 해석·빛 |
| --- | --- | --- |
| [XIX 태양 / The Sun](https://commons.wikimedia.org/wiki/File:RWS1909_-_19_Sun.jpeg) | 위쪽의 얼굴 있는 태양과 교차하는 직선·곡선 광선, 아래쪽 백마와 아이, 붉은 깃발, 돌담, 해바라기 네 송이, 아이의 꽃관·붉은 깃털 | 밝은 아이보리와 금빛 낮. 깃발은 버건디 계열 붉은색. 아이는 짧은 아이보리 천으로 자연스럽게 가리고 순수하고 즐거운 자세 유지. 태양·말·깃발의 실루엣이 먼저 읽힘 |
| [XVII 별 / The Star](https://commons.wikimedia.org/wiki/File:RWS1909_-_17_Star.jpeg) | 큰 팔각별 하나와 작은 팔각별 일곱, 물가에 무릎 꿇은 성인 여성, 물과 땅에 각각 물을 붓는 두 물병, 물 위의 한 발·땅의 한 무릎, 땅 위 갈라지는 물길, 나무와 새 | 고요한 청회색 저녁과 아이보리 별빛. 원본의 비성적 고전 인체 표현, 성인 비례. 인물·물병·두 물줄기를 크게 두고 배경 세부를 억제 |
| [XVI 탑 / The Tower](https://commons.wikimedia.org/wiki/File:RWS1909_-_16_Tower.jpeg) | 바위 위 높은 탑, 위에서 내려치는 번개, 튕겨 나간 왕관, 불꽃, 양옆으로 떨어지는 인물 두 명, 어두운 구름, 금빛 불씨 22개 | 짙은 버건디·청회색 폭풍 속 밝은 석조 탑. 두 인물의 자세·옷 구분. 피나 상처 없이 원본의 극적 사건 유지. 위로는 해석 문구가 담당하고 탑을 평온한 건물로 바꾸지 않음 |

사용자 확정 해석은 수정하지 않는다:

- 태양: 기쁨과 자신감이 일상을 더욱 환하게 비춰줄 거예요.
- 별: 잊고 있던 희망이 다시 반짝이기 시작할 거예요.
- 탑: 흔들린 자리에서 이전보다 단단한 시작을 만들 수 있어요.

전체 22장의 원문은 `card-catalog.json`, 실제 생성에 사용할 공통 및 카드별 지시문은 `sample-prompts.json`에 보관한다. 두 파일 모두 아직 앱에서 import하지 않는 제작 자료다.

### 시안 검수와 스타일 고정

- 세 카드의 피부·석재·물·천을 같은 채색 및 선묘로 처리했는지 나란히 비교한다.
- 100% 확대에서 얼굴·손·말의 해부, 물줄기 연결, 탑·인물의 겹침을 확인한다.
- 별 개수(1+7), 해바라기(4), 인물(탑 2), 불씨(22)는 육안 검수한다. 누락을 추상 장식으로 대체하지 않는다.
- 240px·320px 축소에서도 태양/백마, 인물/물병, 번개/탑이 바로 구분되어야 한다.
- 승인된 태양 원화, 공통 프롬프트, 프레임 버전, 팔레트, 실제 생성 모델·설정·참조 이미지·출처·검수 결과를 기록한다. 별·탑과 이후 19장은 동일 기준 이미지를 참조한다.
- 고정 시드가 가능하더라도 시드만으로 일관성을 보장한다고 가정하지 않는다. 같은 스타일 참조와 검수가 기준이다.

## 4. 체험 흐름과 문구

`8번 테이블 착석 → 소원 타로 → 뒷면 3장 → 한 장 선택 → 선택 결과 로드 → 뒤집기·확대 → 해석 감상 → 꽃다발 받기 → 두 캐릭터의 선물`

- 시작 버튼: **소원 타로**. 안내: **마음에 드는 카드 한 장을 골라 주세요.** 소원 입력창 없음.
- 공통 짧은 안내: **미래를 정하는 예언이 아닌, 오늘의 마음을 위한 작은 위로예요.**
- 테이블 위에 동일한 뒷면 3장을 실제 장면 소품으로 놓고, 체험을 열면 같은 3장 구성을 접근 가능한 선택 버튼으로 확대한다. 두 진입 방식은 같은 회차를 사용한다.
- 선택 즉시 중복 입력을 막는다. 선택 카드 이미지의 `decode()` 완료 뒤 약 450ms 동안 한 번 뒤집고 확대한다. 나머지 두 장은 뒷면을 유지한다.
- 확대 결과는 자동으로 사라지지 않는다. 카드 이름과 확정 해석 하나를 표시하고 **꽃다발 받기**를 누를 때 다음 단계로 간다.
- ‘한 줄 해석’은 원문 한 항목을 의미한다. 작은 화면에서는 자연스럽게 2~3줄로 감싸고, 글자를 축소하거나 말줄임 처리하지 않는다.
- 그림 확대는 화면 폭 약 80~86%, 높이는 `dvh`와 safe area를 고려해 상한을 정한다. 짧은 화면은 dialog 내부 세로 스크롤을 허용한다. 그림은 `contain`으로 전체 구도 보존.
- 두 캐릭터의 빛이 모여 아이보리·연분홍 장미 꽃다발 하나가 만들어지고 왼손으로 이동한다. 꽃 사이 카드에는 이미 불러온 앞면에서 만든 128×192 텍스처를 사용한다.
- 꽃다발을 들고 자리에서 일어나거나 다른 공간으로 이동할 수 있다. 화면 아래 **꽃다발 버리기**를 누르면 꽃다발과 카드가 함께 사라진다. 새 꽃다발을 받으면 들고 있던 꽃다발을 교체한다. 새로고침하면 소지 상태가 초기화된다.
- 결과 후 닫기에도 꽃다발을 받는다. 결과 전 닫기는 체험을 종료한다. 전달 중 자리를 벗어나거나 동작 줄이기를 켠 경우 꽃다발이 왼손에 바로 놓인다.
- 키보드 선택·포커스 복귀·Escape·44px 이상 터치 목표·스크린리더 상태 안내를 지원한다. Escape가 공연장 일어서기까지 전파되지 않게 한다.

## 5. 공정한 추첨과 세션

- 실제 메이저 22장, 정방향만. 이름·해석의 유일한 기준은 카탈로그다. 런타임 AI 해석 생성 없음.
- 회차 시작 시 22개 ID를 균등 Fisher–Yates로 섞어 앞 3개를 각 뒷면 슬롯에 배정한다. 세 장은 회차 내 중복 없음, 회차 사이에는 다시 나올 수 있다.
- bounded 난수는 `crypto.getRandomValues`와 rejection sampling으로 생성한다. 단순 정수 나머지의 편향을 제거한다.
- 어느 위치를 선택해도 각 카드의 확률은 `1/22 ≈ 4.545%`다. 특정 카드가 세 장에 포함될 확률은 `3/22`이며, 결과 확률과 구분한다.
- 결과 선택은 `sessionId + index(0..2)` 한 번으로 고정한다. 재시도·네트워크 재전송·이미지 로드 실패로 다시 뽑지 않는다.
- 온라인은 서버가 배정·선택 결과를 보관하고 선택한 한 장만 응답한다. LocalConcert는 같은 순수 추첨·상태 전이 함수를 사용한다.
- 회차 진행 중 새로고침·재연결은 같은 회차/결과를 복구한다. 꽃 지급도 같은 ID당 한 번만 처리한다. 정상 완료 후 명시적으로 다시 시작한 회차만 새 추첨을 한다.
- 3장만 준비된 시안 단계에서 이를 실제 22장 추첨처럼 서비스하지 않는다. 개발 전용 미리보기는 ‘시안 미리보기’로 표시하며, 정상 체험은 22장 자산 검수 후 활성화한다.

### 착석 검증

UI 표시 조건뿐 아니라 실제 열기·선택·꽃 요청마다 검증한다. `auditorium`, `pose === 'sit'`, `SEATS`에서 찾은 좌석의 테이블 ID가 커플 테이블, 해당 claim의 `visitorId`가 본인이고 `status === 'seated'`여야 한다. 서버가 같은 검사를 수행한다. 걷는 중·예약만 된 상태·다른 테이블·로비·사진 모드에서는 시작하지 않는다. 일어서기/구역 이동/좌석 상실 시 진행 상태와 입력 잠금을 정리한다.

현재 여왕의 `openQueenCardGame()`은 홀 여부만 검사하므로 그대로 복사하면 착석 제한이 빠진다. 타로에는 별도 검증을 둔다.

### NPC 점유 문제 — 해결됨

최초 검토 당시 `NpcBehavior.update()`는 NPC 좌석에 claim이 있으면 해당 캐릭터를 생략했고 NPC 좌석도 `SEATS`에 포함돼 있었다. 후속 사용자 요청으로 NPC 5석을 `SEATS`에서 제외하고 `ALL_SEATS`에만 보존했다. 물리 의자와 NPC를 유지하며 예약·착석·이전 세션 복구에서 NPC 자리 사용을 막는다.

최초 대체 안내 위치 제안은 폐기했다. 실제 구현은 사용자 요청대로 NPC 전용 좌석이며, 이용 가능한 좌석만 정원에 포함한다.

### 공유 꽃 연출

- 개인 카드 결과·문구는 본인에게만 보낸다. 공개 연출은 `{id, recipientId, seatId, startsAt, flowerId}`와 만료 시각만 동기화한다.
- 예시 메시지: `tarotStart`, `tarotChoose`, `tarotFlower`, `tarotClose`; 응답은 개인 세션, 공유 상태는 활성 꽃 이벤트. 이는 설계 이름이며 아직 프로토콜에 추가되지 않았다.
- 서버에서 회차·선택·지급 상태를 저장하고 재전송을 멱등 처리한다. snapshot/delta에는 진행 중인 공개 이벤트만 싣고 정리 시 삭제를 알린다. 재연결 때 이미 끝난 애니메이션을 처음부터 재생하지 않는다.
- `startsAt`과 `net.now()`를 기준으로 두 NPC와 꽃의 시간을 계산한다. 전송은 시작/완료 등 상태 전이 때만 수행한다.
- 여러 관객이 동시에 꽃을 요청하면 테이블별 짧은 전달 순서를 서버가 정한다. 기다리는 동안 닫기 가능, 이탈한 수령인의 대기는 취소. 손짓이 서로 덮어쓰거나 꽃을 중복 지급하지 않는다.
- 선물 꽃 geometry/material은 공유하고 가시 이벤트 수에 맞춰 재사용한다. 새 PointLight·그림자 패스·풀스크린 후처리는 추가하지 않는다.

## 7. 자원과 iPhone 13 Pro 검증 계획

### 이미지 로드·메모리 예산 제안

- 카탈로그는 이미지 URL만 갖는다. 정적 import, 전체 preload, 전체 이미지 atlas, 숨겨진 22개 `<img>`는 사용하지 않는다.
- 테이블에는 작은 뒷면 1개만 로드한다. 개인 결과는 선택된 앞면 1장만 요청하며 React DOM 이미지로 표시해 Three.js에 같은 앞면을 중복 업로드하지 않는다. DOM 이미지도 브라우저 메모리/합성 자원을 쓰므로 비용이 0이라고 보고하지 않는다.
- 모바일 앞면 목표 768×1152, 확대/큰 화면용 1024×1536. 단일 `srcset`과 정확한 `sizes` 또는 선택한 URL 하나를 사용한다. 초기 로드부터 두 해상도를 동시에 디코드하지 않는다.
- 768×1152 RGBA는 약 **3.38 MiB**, 1024×1536은 **6 MiB**다. 이는 디코드 한 장의 산술 추정이며 실제 GPU·프로세스 사용량이 아니다. 밉맵·브라우저 복제본·화면 버퍼·합성 레이어는 별도다.
- WebP 모바일 전송 파일 목표는 카드당 약 200~450 KB로 시작해 선묘 품질을 보며 조정한다. 목표값이며 제작 후 측정해야 한다.
- 앞면 캐시는 활성 결과 1장 기준. 닫기/새 회차 때 DOM과 디코드 자원의 참조 해제, 미완료 요청 취소/오래된 완료 무시. HTTP 캐시와 디코드/GPU 상주는 구분한다.
- 로드 실패는 같은 결과의 재시도 화면으로 유지한다. 다른 카드·추상 그림으로 대체하거나 새 추첨하지 않는다.
- flip에만 `transform`을 쓰고 종료 후 `will-change`를 제거한다. 꽃은 적은 메시와 작은 입자 풀로 끝내며 자원 소유권·dispose를 명시한다.

### 측정 조건과 완료 기준

1. 실제 iPhone 13 Pro + Safari, 기본 low, 전면 탭, 같은 곡·재생 위치·관객 수·8번 테이블 좌석/카메라·뷰포트·렌더 버퍼를 기록한다. 기본 기준은 390×844 CSS px/DPR 3이지만 실제 값을 우선한다.
2. 변경 전 같은 테이블 기준선, 변경 후 평상시, 뒷면 선택, 첫 이미지 로드, 뒤집기, 결과 유지, 꽃 연출을 나눠 측정한다. 각 안정 구간 30초×3회, 최초 로드와 캐시 재진입을 구분한다.
3. 실제 rendered FPS, 프레임 간격 p95, CPU 평균/p95, 지원되는 GPU 시간, draw calls, 삼각형, 텍스처 개수를 기록한다. DOM 카드 flip의 끊김도 따로 관찰한다. `renderer.info.memory`는 바이트 수가 아니다.
4. 종료·재진입 20회 뒤 참조/텍스처/메모리가 계속 증가하는지, 10분 사용 후 발열·음원 끊김·탭 복귀·WebGL 복구를 확인한다.
5. 목표는 기존 모바일 60 FPS. 같은 조건의 기준선 대비 지속 FPS 저하 5% 이내를 임시 회귀 기준으로 두고 100ms 이상 멈춤의 원인을 확인한다. 목표를 실측 결과로 표기하지 않는다.
6. Safari에서 정확한 전체 메모리나 GPU 시간이 노출되지 않으면 미측정으로 명시하고 Inspector 측정 가능 항목·자원 개수·디코드 산술 추정을 구분한다. PC 모바일 뷰포트 결과를 실기기 결과로 대신하지 않는다.

현재 실기기 측정 없음. 기존 진단의 PC용 iPhone 화면 모사와 실제 iPhone 측정 경로를 구분한 상태다.
