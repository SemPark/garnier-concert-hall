# 공개 사이트 모바일 렌더링 점검 — 2026-10-30

대상: https://sempark.github.io/garnier-concert-hall/

수정 전 57d72ca, 수정 후 0f9ec2e. Ego Lite Chromium에서 공개 GitHub Pages 주소를 직접 열었다. 로컬 웹 서버를 사용하지 않았다. Apple M4 / ANGLE Metal 환경에 390×844 CSS viewport, DPR 3, CPU 4배 제한을 설정했다. 캐시 비활성화로 배포 자산 로드를 확인했다. 이는 실제 iPhone Safari GPU·발열·메모리 환경을 재현한 검사가 아니다.

## 관측 결과

각 장면을 약 4초씩 측정한 requestAnimationFrame 간격이다. 다른 기기의 FPS를 보장하지 않는다.

| 공연 가까이 | 74.74 | 75.00 | 15.1 / 14.2 | 0 |

양쪽 모두 이 테스트 장비의 약 75Hz 상한에 도달했다. 실제 아이폰에서 보고된 심한 프레임 저하는 재현하지 못했다. 이 숫자를 FPS 향상으로 해석하지 않는다.

- 기본 렌더 버퍼: 390×844 → 624×1350. antialias false → true. 실제 공개 페이지 캔버스와 WebGL 속성으로 확인했다.
- 가까운 공연 시점: 68 draw calls / 303,652 triangles. 걷기 측정 종료 시점: 91 calls / 261,892 triangles. 카메라 위치에 따라 달라지므로 이전 고정 시점 수치와 직접 비교하지 않는다.
- 화면 품질 선택: 선명하게 780×1688, 가볍게 390×844, 균형 624×1350. 모바일 설정 패널 가로 넘침 없음.
- 공개 페이지 JS는 index-DTM2E17b.js로 확인. 음원 재생 상태와 모바일 음악 메뉴 접힘을 확인했다.
- 시작·셰이더 준비 중 long task는 남아 있다. 이번 로드에서 최대 1,057ms, 공연장 전환 근처 94ms를 관측했다. 지속 감상·이동 중에는 위 측정 구간에서 long task가 없었다. 로드 시점은 비교 세션마다 조건이 달라 개선율을 주장하지 않는다.

## 적용 내용

- 단원의 몸통·다리·고정 악기를 한 번만 인스턴싱하고, 머리·팔만 30Hz로 갱신한다. 기존 원거리 4Hz 동작 갱신을 제거했다.
- 고정 배치는 카메라가 움직이고 거리별 표시 그룹이 달라질 때만 행렬을 업로드한다. 인스턴스 색상도 멤버 구성이 달라질 때만 업로드한다.
- 비금속 표면은 Lambert 재질로 바꿔 조명 계산량을 줄이고 금속은 기존 재질을 유지했다.
- 원거리 악기는 상자 대신 원래 외곽선을 단순화한다. 샹들리에 원거리 실루엣을 유지한다.
- 자동 0.85배 해상도 하향 제거. 기본 Retina 1.6배 및 antialias, 사용자가 고르는 3개 화질 모드를 제공한다. 설정에서 FPS와 렌더 해상도를 표시한다.
- 렌더 비율에 픽셀 예산을 적용해 큰 화면에서 무제한 증가하지 않게 했다. 프레임 간 이동 시간 제한을 완화해 낮은 FPS에서 이동 속도가 과도하게 줄지 않게 했다.

타입 검사, 31개 단위 테스트 및 GitHub Pages 프로덕션 빌드 통과. 고정 몸통의 불필요한 재업로드 방지와 이동 팔 갱신, 화질별 픽셀 예산을 검사한다. 실제 iPhone Safari에서의 성능 확인은 남아 있다.
