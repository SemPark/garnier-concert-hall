# PLEEE 영상 모션 추출 도구

## 실행과 입력

```sh
npm run dev:motion
```

개발 화면: http://127.0.0.1:5173/motion-lab.html
이미 `npm run dev`를 실행 중이면 같은 URL을 연다. iPhone용 개발 서버에서는 포트 5174를 사용한다.
이 도구는 Vite 개발 전용이며 운영 빌드에는 페이지·MediaPipe·추출 Worker가 들어가지 않는다.

1. 정면 MP4/WebM 파일이나 링크를 연다. 같은 동작을 동시에 촬영한 약 90° 측면 영상도 파일이나 링크로 추가할 수 있다. 원본 재생 막대로 같은 동작의 시각을 찾아 측면 시각에서 정면 시각을 뺀 값을 **측면 시간차**에 입력한다. 측면 영상의 시작 포즈에서 사람이 향하는 화면 방향을 선택한다.
2. 동작 ID(기본 `captain`), 시작·끝(1~60초), FPS(15/24/30)를 지정한다.
3. **동작 추출**을 누른다. 진행률을 확인하고 필요하면 취소한다.
4. 원본 관절 표시와 같은 시각의 기존 캐릭터 정면·측면을 확인한다. 재생/일시정지와 슬라이더로 반복 경계를 확인한다.
5. **모션 JSON 저장**으로 내보낸다. 저장한 모션 열기로 원본 영상 없이도 미리 볼 수 있다.

링크는 브라우저가 읽을 수 있는 직접 영상 리소스여야 한다. 확장자가 없는 서명 URL도 허용한다.
외부 서버는 CORS를 허용해야 하며 영상 코덱은 브라우저가 지원해야 한다. YouTube/Instagram/TikTok/Vimeo 페이지를 다운로드하거나 접근 제한을 우회하지 않는다. 이런 영상은 사용 권한이 있는 파일을 선택한다.
영상은 외부로 업로드하지 않는다. URL 입력 시 해당 영상 서버에 접속하며 최초 분석에는 jsDelivr의 고정 MediaPipe Tasks Vision 0.10.21과 Google의 Pose Landmarker full float16 v1 모델을 내려받는다. 유료 API·키·결제는 없다.

원본 영상의 재생 버튼을 누르면 영상 아래에 브라우저에서 관측한 FPS가 표시된다. 프레임 간격이 일정하지 않으면 변동 표시가 나온다. 이 수치는 재생 환경에서 측정한 값으로, 파일 메타데이터나 추출 결과의 FPS와 다를 수 있다. 캐릭터 미리보기는 30 FPS를 목표로 갱신한다.

## 공연장 적용

검토한 JSON을 `src/motion/clips/`에 넣고 앱을 다시 빌드한다. `id: "captain"`이면 사람 아바타의 기존 선장춤을 대체한다. 파일이 없으면 기존 춤이 그대로 유지된다. 중복 ID와 잘못된 형식은 로딩 시 경고하고 제외한다.

기존 서버의 `CAPTAIN_MOVE_MS` 주기에 클립 시간을 맞춰 같은 시각을 재생한다. 원본 길이가 기존 주기와 다르면 재생 속도가 달라지므로 해당 주기와 비슷한 구간을 추출하는 것이 좋다. 새 동작은 다른 ID로 저장해 `applyMotion(avatar, clip, seconds, weight)`를 재사용할 수 있다. 새 공연장 버튼·동작 등록은 별도로 공유 dance 규약과 연결해야 한다. 인스턴스 유령 NPC는 기존 간략 춤을 유지한다.

JSON은 27채널(몸 이동·회전, 머리 회전, 양손 목표와 팔꿈치 방향, 양발 목표)의 균일 간격 키프레임이다. 4자리 소수로 저장하며 마지막 프레임은 처음과 같다. 영상·원시 관절·모델은 공연장에 포함하지 않는다. 런타임은 두 키프레임의 보간과 기존 IK만 수행하고, 프레임마다 모델 추론·네트워크 요청·새 모션 버퍼 할당을 하지 않는다.

## 캐릭터와 보정

기존 `Avatar`는 SkinnedMesh/Skeleton이 아닌 Group 부품 구조다. 이미 있는 선장춤 상완/전완과 다리 IK를 재사용하며 캐릭터 외형·메시·재질은 새로 디자인하지 않는다. 일반 동작으로 돌아갈 때 기존 update 경로가 팔과 발 상태를 복구한다.

- 좌표: MediaPipe 카메라 좌표를 캐릭터의 +Y 위, -Z 앞 방향으로 변환한다. 정면·고정 카메라를 가정한다.
- 신체 비율: 상완 .216, 전완 .203, 다리 .49의 기존 길이를 사용한다. 원본 사람 비율로 메시를 늘리지 않는다.
- 추적: 필요한 관절 visibility .5 미만 프레임을 손실로 처리한다. 짧은 손실은 양쪽 프레임을 보간하고, 전체 20% 초과 또는 연속 .5초 초과 손실은 저장을 거부한다.
- 흔들림: 양방향 5Hz 저역 필터와 급격한 변위 제한을 적용한다.
- 발: 낮은 높이·낮은 속도의 발을 접지점에 고정하고 기존 두 관절 IK로 발 목표를 푼다.
- 루프: 마지막 약 .3초를 첫 포즈로 부드럽게 연결한다. 비슷한 포즈에서 구간을 자르면 더 자연스럽다.
- 이동: 이미지상의 골반 변위를 신체 크기로 환산한다. 공연장 위치·충돌 기준을 보존하도록 수평 이동은 ±12cm로 제한하며 깊이 이동은 추출하지 않는다.

## 한계

단일 영상의 가려진 관절·깊이는 추정치다. 빠른 회전, 교차한 팔, 여러 사람, 화면 밖 발, 흔들리는 카메라에서는 정확도가 떨어진다. 손가락과 손목 비틀림은 추출하지 않으며 머리·몸 기울기는 제한된 근사다. 이 도구는 캐릭터 비율에 맞춘 동작 재현용이며 정밀 모션 캡처를 보장하지 않는다.
발 미끄러짐·관통·루프의 속도 변화는 보정으로 줄이지만 완전히 제거하지 못한다. 깊은 런지와 큰 점프는 캐릭터의 짧은 다리와 이동 제한 때문에 달라질 수 있다. 측면 원본이 있으면 화면 가로 좌표를 몸통 크기로 환산해 관절 깊이에 반영한다. 측면에서 가린 관절은 정면 모델 추정값을 쓰며, 결과에 반영률을 표시한다. 이 방식은 두 고정 카메라가 약 90°를 이룬다고 가정한다. 카메라 위치와 렌즈를 보정하는 정밀 삼각측량과 정확도가 다르다. 정면만 넣은 경우 캐릭터 측면은 단안 추정이다.

iPhone 13 Pro를 위해 공연장에는 AI 분석 코드를 넣지 않는다. 개발 도구는 추출 입력을 최대 너비 640px로 줄이고 별도 Worker를 사용하며 미리보기는 30FPS/DPR 최대 1.5로 제한한다. 추출은 데스크톱 사용을 권장하며 iPhone의 실측 FPS·발열·메모리·Safari 호환성은 아직 확인하지 않았다.

## 검증

- `npm run check`, 관련 모션/춤 테스트 19개, `npm run build` 통과. 기존 빌드의 큰 번들 경고는 유지된다.
- 실제 브라우저에서 Google 공개 pose.jpg를 2초 MP4로 만든 입력으로 MediaPipe 추론 → 49키프레임/약 8.9KB JSON → 정면/측면 미리보기 확인. 이 영상은 정지 이미지 기반 파이프라인 검사이며 춤 재현 정확도 측정이 아니다.
- 로컬 파일과 직접 영상 URL의 추출, 일반 서비스 페이지 URL 거부, 추출 취소, JSON 다운로드·재불러오기·동기 재생을 브라우저에서 확인했다.
- 49개 프레임에 걸친 캐릭터 변환 4,263개가 모두 유한한 값이며 일반 애니메이션으로 돌아갈 때 양손이 기존 부모로 복구됨을 확인했다.
- 테스트용 영상·모션은 배포용 clips 폴더에 등록하지 않았다. 운영 번들에 MediaPipe/추출 Worker가 없음을 확인했다.
- 실제 꼬마 선장춤 영상과 iPhone 13 Pro 실기기 검증은 미실시.
